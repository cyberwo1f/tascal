# 未決事項・課題トラッカー

実装前に決めるべき論点を一元管理する。**セッションをまたいでもここを見れば現状が分かる**ようにする。
決まったものは「状態」を更新し、必要なら [`adr/`](./adr/) に決定記録を残し、関連ドキュメントへ反映する。

## 使い方
- 新しい論点が出たら ID（`Q-<分類>-<連番>`）を振って追記する。
- 状態：🔴 未決 / 🗣 質問中 / 🟡 暫定方針あり / ✅ 決定 / 💤 保留（将来）/ ✖ 取り下げ（非目標化）。
- 重要度：高（実装の前提を規定）/ 中 / 低。
- 「今回質問」列に ★ が付くものは、現在ユーザーに確認中。

## ビジョン更新メモ（2026-06-18）
ユーザーの意向：**将来的に「AI 社員」を管理し、タスク/ミッションを与えると自律行動し、AI が
エスカレーション・確認・回答を求めるときにユーザーへ Post するサービス**にしたい。
→ 柱④を「AI 協働」から「**AI 社員のマネジメント**」へ発展させる北極星として記録（Q-AI-7〜9）。
また、機能の追加検討・洗い出し・ビジョン調整を**継続的に**行いたい（→ product-spec の「アイデア・バックログ」）。

## ビジョン更新メモ（2026-06-19）
- ミッションを追加：**「AI 格差をなくし、AI をより身近にする」**（vision.md）。一人ではやり切れない規模を
  あえて可視化し、AI でマルチタスクを可能にして「コミットメント最大化」へ導く。AI の使い方を知らなくても UI/UX が導く。
- この思想から **Q-PROD-2 を「第一級エンティティ化」で決定**（ADR-0001）。約束は「1 約束＝複数作業」を表せる構造にする。
  柱①（設定最小）とは **段階開示・原則任意** で両立（単独ユーザーは今と同じ軽さ）。
- **シーケンス**：コミット可視化（M4）と AI 最小形（M3）は**分離維持**。AI 実装**前**に構造を人手で確かめる（de-risk）。
  最終形（落としどころ・記録）は「リッチな約束モデル＋**AI による構造の充填**＋段階開示」。
- 機能の洗い出し・ブラッシュアップの全体像は [`proposals/2026-06-19-feature-brushup-proposal.md`](./proposals/2026-06-19-feature-brushup-proposal.md) を参照
  （Q-PROD-1/3、足回り機能、AI 段階ロードマップ等の**提案**を収録。Q-PROD-2 以外は未確定）。

## ビジョン更新メモ（2026-06-20）
- **「一人で捌き切る」ことに特化へ再調整**（[ADR-0003](./adr/0003-single-person-focus.md)）。柱①「一人〜少人数の管理」→「一人で捌き切る」。
  膨大なマルチタスク × AI コラボ × 可視化という核は**個人視点で完結**するため、視点を個人に固定。
- **マルチユーザー管理（他者共有・担当者割り当て・権限ロール）を非目標化／廃止**。**Q-PROD-4 取り下げ**。Workspace/Membership は持たない。
- **M2 を「データ基盤・端末間同期（単独ユーザー）」へ再定義**（本人アカウント＋自分のデータ同期のみ）。時期は Q-ARCH-2 に従属（→ **Q-PROD-7** 新設・💤）。
- **保持**：①`stakeholder`（外部の約束先・自由記述）②**AI への委任（owner=AI / `ownerType:'ai'`）は将来必要**として柱④・北極星（M7）で扱う。人間同士の割り当てのみ廃止。

### (II) 効果が薄い項目（単独特化で価値低下 → 遅延/簡素化を推奨）

- **`owner`（人間）フィールド**：単独では値が常に「自分」＝分散ゼロで情報量ゼロ。意味を持つのは AI=owner 登場後。**M4 で作らず AI フェーズへ**（提案の方針に合わせる）。
- **`stakeholder` の構造化**：単独では「頭の中にあり構造化価値が薄い」（提案 I-5/I-8）。**自由記述/タグ（`@顧客名`）に留める**（フィールド化・構造化はしない）。
- **`softDue`（二重締切）**：柱①（設定最小）に最も反し、単独で便益が出る場面が少ない。**遅延維持**。
- **ActivityLog / 変更履歴（現 M2）**：監査ログの価値は多人数の説明責任から来る。単独では自明で効果薄。価値が戻るのは **AI 社員の行動ログ（M7）** → M2 から AI フェーズへ寄せる。
- **達成リングの「担当者別」軸**：担当者が自分1人の間は1本しか出ない。human+AI が並ぶ **M7 まで前倒し不要**。

### (III) 戦略リスク（→ Q-PROD-8）

- チーム軸を外したことで差別化が **柱④（AI）へ一極集中**。AI は最も後段（M3 保留 / M7 北極星）で、立ち上がるまでの“谷”では「AI なしの単独コミットメント管理」＝既存個人向けツールと正面競合（スイッチングコストが低い領域）。
- **北極星 M7（AI 社員管理）は構造的にマルチユーザー機構と同型**（複数アクターの割り当て・別 owner 集計・行動ログ・通知/エスカレーション・権限/自律度）。非目標化で owner/assigneeId/ActivityLog を**残した判断は妥当**だが、権限/自律度は **Q-AI-2 が単独で担う**点を見落とさないこと（上表に注記済）。
