# ADR-0003: 「一人で捌き切る」ことに特化し、マルチユーザー（他者共有）を非目標化する

- **状態**: 承認
- **日付**: 2026-06-20
- **関連**: Q-PROD-4（取り下げ）、Q-ARCH-2 / Q-BIZ-1 / Q-AI-9 と連動。柱①の再定義。[ADR-0001](./0001-commitment-model.md)（コミットメントモデル）を前提に補強。

## 背景 / 課題
これまで Tascal のターゲットは「**一人経営・少人数チーム**」、柱①は「**一人〜少人数の管理に特化**」と置き、
ロードマップ M2 に「データ基盤・マルチユーザー（アカウント・他者との共有・担当者割り当て・権限ロール）」を据えていた。

一方でプロダクトの核は、**膨大なマルチタスク（一人ではやり切れない規模）を AI コラボレーションで捌き切り**、
その環境下で必須となる**コミットメント／マイルストーン進捗の可視化を徹底する**ことにある（柱②③④・[ADR-0001](./0001-commitment-model.md)）。
この核に照らすと、**視点を「個人（一人）」に固定した方がプロダクトとしての合理性が高い**：

- 「一人ではやり切れない規模」を可視化し AI で捌く、という体験は**個人視点で完結**する。複数人の管理は核ではない。
- 他者との共有・担当者割り当て・権限といった**マルチユーザー管理の必要性は現時点で弱い**。
  これらを抱えると柱①（設定最小）と恒常的に緊張し、認証・権限・同期の実装コストが核の検証を遅らせる。

## 決定
**ターゲットと柱①を「一人で捌き切る」ことに再定義し、マルチユーザー（他者との共有）を非目標化する。**

- **柱①**：「一人〜少人数の管理に特化」→ **「一人で捌き切ることに特化」**。
  膨大なマルチタスクを**一人**（＋AI）で回し切ることを可能にする観点に絞る。
- **ターゲット**：一人経営者・フリーランス等の**個人**。「少人数チーム（2〜10 名）」は主対象から外す。
- **非目標に追加**：他者（人間）との共有・担当者割り当て・権限ロール（マルチユーザー管理）。
- **ロードマップ M2** は「データ基盤・マルチユーザー」から **「データ基盤・端末間同期（単独ユーザー）」** へ再定義。
  認証は**本人のアカウント**と**自分のデータの端末間同期**のためにのみ用い、Workspace / Membership / 共有プロジェクト / 人間同士の割り当て / 権限ロールは**廃止**する。

### 保持するもの（重要）
- **owner に AI を割り当てる機能（`ownerType:'ai'`）は将来必要**として残す。
  「人間同士の割り当て」は廃止するが、**AI 社員へタスク／ミッションを委任する**仕組みは
  AI コラボレーションの課題に対して必要であり、**柱④／北極星（M7）**で扱う（Q-AI-9）。
  ＝「割り当て（assignment）」概念は**人間→AI 委任の用途で生き続ける**。
- **相手 / 宛先（`stakeholder`）**：誰への約束か（顧客等の**外部の宛先**）は、単独利用でも価値があるため
  **自由記述の任意項目として保持**する。これは「管理対象のユーザー」ではなく**約束先のラベル**であり、マルチユーザー化とは独立。
- **単独ユーザーのクラウドアカウント／端末間同期**は将来像として残す（Web / デスクトップ / 将来モバイルで“自分の”データが繋がる）。
  実装時期は Q-ARCH-2（データ基盤の判断）に従属。

## 検討した選択肢
- **案A：一人特化へ再定義し、他者共有を非目標化**（採用）。核（膨大マルチタスク × AI × 可視化）と一致し、柱①の緊張を解消。
- **案B：従来どおり「一人〜少人数チーム」を維持**。共有・権限・割り当ての実装が核の検証を遅らせ、現時点で必要性が弱い（不採用）。
- **案C：個人全般へ拡大（経営者に限らない）**。将来の検討余地として残すが、今回はペルソナ（一人経営者・フリーランス）を維持し、変更は「チーム前提を外す」ことに限定。
